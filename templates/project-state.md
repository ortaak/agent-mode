# Project State

Single source of truth for the project's current status. Keep it under 100 lines. Update it at the end of every task. Rewrite stale sections instead of appending history (history belongs in the changelog).

- **Project**: name
- **Last updated**: YYYY-MM-DD
- **Stack**: languages, frameworks, database, hosting
- **Run locally**: the 3-5 commands needed to start the project
- **Check command**: the command(s) that verify the project

## Current status
- Phase: (for example: MVP build, stabilization)
- Current focus: one sentence

## Architecture at a glance
- Main folders and what they contain (one line each)
- Key external services

## Decisions
- Link to ADRs in `docs/decisions/`, with a one-line summary each

## Open work
- [ ] Task, with priority and the file or area it touches

## Known issues
- Issue, impact, workaround

## Conventions
- Naming, error format, API response format, or other project rules that are not obvious from the code
